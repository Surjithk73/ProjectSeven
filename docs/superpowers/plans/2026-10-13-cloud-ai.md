# Google Cloud AI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Configure the working service-account credential in the local browser app and verify Gemini 3.8 Flash repairs through the existing engine.

**Architecture:** A small immutable runtime connection holds controller-only credentials; the local job service owns its session selection and captures it for each repair. The existing SDK generator receives that connection separately from untrusted prompt data. Browser settings, CLI and the existing live acceptance runner share connection construction and safe metadata.

**Tech Stack:** Existing Python/FastAPI, google-genai 2.22.0, httpx 0.28.1, google-auth 2.57.1, React/Lucide/CSS, pytest and Node tests. Declare google-auth directly at its installed version because production code will import it directly; no provider framework or new UI library.

**Spec:** `docs/superpowers/specs/2026-10-13-cloud-ai-design.md` (written design approved by the user).

## Global Constraints

- Work in `C:/Users/surji/.codex/worktrees/apishield-phase1/ProjectSeven`; preserve the original repositories and existing local/no-login experience.
- Cloud delivery uses the service-account project, global location and Gemini 3.8 Flash. The earlier API keys are not fallbacks; ambient SDK flags cannot select a provider.
- Credentials stay in controller memory for the app session, with no private key/token/credential path in configs, jobs, logs, prompts, patches or repository subprocess environments.
- Credential JSON is at most 64 KiB; accept service accounts only and the fixed HTTPS Google OAuth endpoint. No delegated subject, custom API endpoint or proxy.
- OAuth refresh and model calls share the request's remaining deadline. Disable ambient proxies and SDK content retries; preserve finite engine attempts, cancellation and protected tests/contracts.
- Live acceptance is one repeat of six scenarios, at most two attempts each: maximum 12 generation calls plus one tiny application connection test. Maximum generation output is 4096 tokens per call.
- Never modify tests/oracles to make proposals pass, silently rerun successes, substitute models, merge/publish GitHub changes or change Cloud billing/permissions in this subsystem.
- Research evaluation, patent work, hosting and early trials remain deferred. GitHub drafts, deeper analysis and environment setup remain the subsequent separate subsystems.

## Review Focus

- A malformed/oversized credential submission contains private material: local validation/error responses must not echo or retain it (Tasks 1–2).
- OAuth refresh consumes most of the deadline, or protocol bytes arrive slowly: generation receives only the remaining budget and total network waiting remains bounded (Task 1).
- Settings are replaced/cleared during a queued or retrying job: that job keeps its captured provider, while new jobs observe the new selection (Task 2).
- Cloud is configured while GEMINI_API_KEY/SDK flags point elsewhere: readiness and requests use the selected route without silent fallback (Tasks 1–2).
- Instrumentation or an independent validation failure occurs mid-batch: retained outcomes remain truthful, credentials stay absent, and the paid-call ceiling remains intact (Task 4).
