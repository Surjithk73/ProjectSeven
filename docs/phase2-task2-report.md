## Interfaces and behavior

- `apishield.engine.run_job(config, operation, store, candidate_path=None, job=None)` matches the plan and is shared by CLI/dashboard. `scan_sources(workspace, code_paths)` returns sites, files scanned and explicit coverage limitations. `generate_candidate(context, feedback=None)` is injectable at the engine boundary for offline retry tests.
- Direct requests/httpx GET/POST calls support import aliases, URL constants/assignments, concatenation, literal f-strings and late stable module globals. Unknown URL expressions, reassigned globals and wrapper/client-instance calls remain limitations; no endpoint is guessed. Sites include file/function/line/method/endpoint and optional explicit Business Intent.
- Native oasdiff is resolved from explicit `OASDIFF_BIN`, PATH, then the development Windows executable under `tools/`. Comparison uses copied contracts, a clean evidence cwd, bounded sanitized command execution, disabled external references and strict complete JSON evidence. Changed operation localization matches normalized path parameters; shared component/security/server changes conservatively impact all operations.
- Repairs accept explicit offline `{patches:[{file,old_code_snippet,new_code_snippet}], needs_input?:str}` JSON or the explicit Gemini generator. Offline candidates are evaluated once and never switch to inference. Live generation has bounded attempts, request deadlines capped by remaining job budget, one SDK attempt, explicit exported `GEMINI_API_KEY`, explicit non-Vertex/non-enterprise mode, disabled ambient proxy settings, complete source and schema data framed as untrusted. No target dotenv or legacy root agent/config module is imported.
- Every repair attempt restores the pinned committed tree. Candidates can edit only localized configured Python source; tests/config/contracts/unrelated files are rejected. Exact snippets must match once, replacements cannot overlap or be no-ops, and all grouped files must parse before any are changed. Multi-file patches and CRLF bytes are supported.
- Configured `python` and `python3` executables resolve to the controller interpreter for active-environment validation. Setup/tests run via Task 1 bounded sanitized process ownership. Independent byte/mode inventories reject changes to protected original repository files, altered candidates, added test hooks/config/source and contract snapshots; committed files inside cache directories remain protected. Only newly generated known Python/pytest cache files are exempt. Setup may use external environments, but cannot create/change repository files outside those caches. All configured tests run; no tests or unspecified behavior produces `needs_input`.
- Passing tests retain `candidate.patch` only after independent checks. The original source checkout is unchanged. Terminal publication rechecks Task 1 contract creation bytes and pending cancellation; unvalidated/cancelled jobs remove patch artifacts. Disposable workspace cleanup occurs on all engine terminal paths.
- Cross-process OS `execution.lock` ownership prevents duplicate execution. `worker-owner.json` preserves the dashboard's separate owner marker. Running reports persist pinned revision and scan/comparison evidence. `recover_interrupted(store, job_id)` classifies a running job without live lock ownership as failed/interrupted, preserves evidence and removes disposable source/patch; partial repairs are never resumed or labeled validated.
